## 1. 产品定位

灵犀手机客户端是既有灵犀工作台的离线优先 Android 工作客户端：断网时仍能录音、本机中文转写、编辑记录、阅读和检索已下载工作副本；服务恢复后同步已授权内容，并继续使用同一工作台的 Agent、知识和结果。交付物是可安装的签名 APK，不是网页链接、PWA、HAP 或只有在线 WebView 的包装。

手机负责低延迟交互、硬件采集、本地计算、持久工作副本及同步；工作台负责 DSH、正式知识组织、远程 Agent 和实际任务结果。原生界面还是内置 Web UI 加原生模块由 ED 选型；不得强制重写已有后端，也不得依赖首次加载公网网页才能进入离线界面。

## 2. 一套知识，两个工作端

正式知识仍由工作台管理的 NJX-Knowledge 提供 note_id/revision。手机保存草稿、未同步编辑、原始录音和用户选择的离线副本，不建立第二套独立 Wiki/向量索引/长期记忆后台。GitHub 是项目代码与治理事实源，不是私人录音和运行数据的默认同步目标。

数据层区分原始采集、设备转写、用户修正版、工作台补充转写/整理及正式知识版本。自动校正或重新整理不覆盖原始资料，不覆盖 Owner 手工修正。草稿默认不上传；用户点击“交给灵犀”或明确开启自动提交后，才形成可自动补传的授权队列。

## 3. 手机体验

主导航为“灵犀 / 记录 / 知识 / 我的”。保留工作台既有视觉语义、知识名称与结果表达，不压缩桌面三栏到小屏，不造第二套品牌。首页以 Agent 协作和持续可见的采集入口为核心；离线时展示本机能力与待同步数量，而不是空白页或无尽转圈。

“灵犀”：在线会话、已有任务及结果；离线看已下载会话、准备问题，并明确选择联网后发送。没有本地语言模型时不伪造离线 Agent 回答。
“记录”：原生录音、语音转文字、文本编辑、照片/文件及系统分享入口；记录先落盘，查看原音频、转写和修订；草稿、待同步、服务处理中、需处理各有清楚状态。
“知识”：在线使用既有检索和内容；用户可下载指定笔记/结果，离线阅读、文本检索、修改可编辑笔记副本；未下载内容明确不可离线打开。PDF/Office 等附件不冒充具备全格式离线编辑能力。
“我的”：连接、设备权限、中文离线识别可用性、同步策略、缓存容量和恢复操作；工程诊断不占首屏。

## 4. 硬件与离线能力

本机中文语音转文字是本轮必交能力，不降级为“录音留着以后上传”。先验证目标机的离线系统识别能力；不满足时由 ED 选择可本机运行的识别实现。运行不得强依赖 Google 服务或未验证的芯片加速接口。CPU 可作为基本路径，NPU/GPU 优化由实际能力决定；不得声称已经使用未验证的加速器。

首次离线测试须已具备识别资源：随 APK 提供或复用已验证的本机服务；不得在飞行模式下等待在线下载、鉴权或识别。失效时应保存原音频并报告恢复动作，但该故障回退不算离线转写通过。

已保存内容和待同步队列使用持久存储；它们与可清理下载缓存分离。清缓存不删草稿、未同步修订、未确认接收的音频。重开和重启后可恢复；卸载/清除应用数据不是承诺保留的场景，应在相关说明中明确。录音由用户主动启动，切后台/锁屏按系统允许机制继续并保持可见状态；被系统终止或被用户强停后不伪称仍在录音。

## 5. 同步及工作台协作

本机保存→已授权待同步→上传→工作台可靠接收→排队/处理→实际结果→手机回显，传输和处理分开。联网不等于服务可达；工作台关机/会话过期时仍可本地工作。重传幂等、断传恢复、迟到资料按采集时间关联、版本冲突保留双方而不静默覆盖。

正式笔记修改附带基准 revision；冲突由用户选择保留/合并，原始副本不丢。同步成功不等于知识整理或 Agent 执行完成。离线排队的外部发送/删除等敏感动作，恢复网络时仍要经过适用的确认，不能把旧排队视为无限执行授权。

## 6. 安全、范围与生命周期

单用户/<10 用户，保护私密知识、原音频、认证及不可逆操作。手机存储及传输按此风险保护，凭证使用平台安全存储，日志与截图脱敏；不添加无关企业防线。

本轮为 PRE_1_0 私人测试 APK 增量，不声明最终 1.0 或生产发布。真实硬件测试采用合成资料并遵守本机权限；工作台仍隔离运行。摄像/文件/分享属于采集接入，完整 OCR、多模态理解、手机全量大模型、声纹认证、后台常听、手表/健康连接、商店上架及全量知识库镜像不自动进入。
