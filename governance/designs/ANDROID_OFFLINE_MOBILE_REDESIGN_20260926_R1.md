## 1. 产品定位

**灵犀移动端是随身可离线工作的灵犀客户端：手机承担即时交互、采集、本地语音转文字、可靠保存和工作副本；工作台承担共享知识、复杂 Agent 处理、整理、索引和能力调用。**

不是远程桌面，不是每次启动都必须加载公网网址的网页壳，也不是把整套 DSH 和知识后台搬到手机。

复用既有工作台的产品语义、视觉语言、会话与资料能力；按手机使用场景重新组织界面。是否复用 Web 组件、哪些部分原生实现，由独立 ED 依据现有代码和设备验证决定。产品侧不指定未经验证的技术栈。

## 2. 一次真实使用应该是什么样

用户在无网环境打开 App，按一下录音，说出一段内容。App 保存原始录音，在本机生成可修改文字。用户补充标题、改正一个词，关闭 App。

再次打开时，录音、文字、修改记录仍在。用户能搜索、回听，也能查阅此前下载的资料。没有网络时，不出现无限加载的“正在连接灵犀”。

网络恢复且工作台可达后，用户此前授权提交的内容自动上传；仅保存为草稿的内容不会被擅自发送。工作台真正接收、处理、生成知识结果后，手机得到对应结果。原始资料、用户修改、后台整理结果可以分别查看。重复点击或断网重传不会生成多份相同笔记。

若手机已经联网而 Mac/工作台离线，仍保留全部本地工作，显示“等待工作台连接”，不冒充已同步。

## 3. 手机端信息架构

底部四个入口：**灵犀 / 记录 / 知识 / 我的**。语音录入在主界面第一屏可达。

| 页面 | 主要内容 | 交互要求 |
|---|---|---|
| 灵犀 | Agent 对话、继续上次工作、最近结果、当前连接状态 | 输入区适合单手操作；文本、录音、添加资料同处；区分本地记录、待发送消息、工作台回答 |
| 记录 | 按采集时间组织的记录、草稿、待同步、处理结果 | 默认展示当前真实状态；可搜索、编辑、回听；错误有明确恢复动作 |
| 知识 | 已下载资料、收藏、最近查看、联网知识检索 | 离线只搜索本地可用内容并明确范围；展示资料版本和同步时间；未下载的内容不能假装可读 |
| 我的 | 工作台连接、离线资源、语音模型、存储空间、同步策略、权限 | 诊断信息不占据首页；可暂停上传、管理下载、查看待处理问题 |

### 录音工作面

从主界面一触即达。录音中展示录音状态、时长、暂停/继续、停止保存；转写区域允许显示处理中但不能妨碍录音保存。停止后进入记录详情，可回听、修正、补充、明确“交给灵犀”。

转写失败时，原始音频仍可用，能在本机重试；不得因为 ASR 失败导致录音丢失。低质量/近静音内容给出提醒和重录入口。锁屏录音须有可见系统提示和停止入口，禁止隐蔽持续采集。

### 记录详情

先显示用户可编辑内容，再提供“原始录音 / 本地初始转写 / 我的修正 / 灵犀整理结果”。默认展示最相关内容，而不是工程日志。最多两次导航可找到原始来源。

### 移动视觉继承

保留灵犀工作台的视觉辨识和内容层级，但不把桌面三栏压缩到手机。图谱、资料和能力工作面按上下文展开；核心记录、编辑、回看不能依赖远程网页。设计追溯和真实手机截图是交付证据，旧 HAP 截图不得作为 Android 成果。

## 4. 在线与离线能力合同草案

| 能力 | 离线行为 | 联网后的行为 |
|---|---|---|
| 启动与导航 | 核心界面本地可打开；不因登录服务暂不可达而抹去本地草稿 | 恢复工作台连接并显示真实状态 |
| 文本记录 | 新建、编辑、保存、搜索本地记录 | 提交已授权的变更，返回后台处理结果 |
| 录音 | 开始、暂停/继续、停止、保存、回听 | 按提交策略上传原件和转写 |
| 语音转文字 | 在已准备离线模型的前提下，普通话在手机完成；第一版必做 | 可选择由工作台进一步校正，保留本地文字和用户修改 |
| 资料查看 | 可阅读明确下载的支持格式；下载状态真实 | 获取新版本、下载更多资料 |
| 文件导入 | 选择手机实际可访问的文件并可靠保存为记录；不承诺所有格式都可本地解析 | 调用工作台已验证的解析能力；上传与解析分开显示 |
| 会话 | 可查看已下载历史、写本地草稿或明确排队的问题 | 用户已授权的问题恢复发送；不因恢复网络擅自执行敏感命令 |
| 知识整理、全库检索和复杂 Agent | 不伪装成在线结果；可保存请求，明确等待工作台 | 调用既有 DSH 和知识处理能力，结果回传 |
| 同步 | 持久队列保留；允许暂停、取消尚未发送的提交 | 前台自动恢复；后台在系统许可时尽力执行，回到前台补齐 |

“离线可用”不等于完整离线大模型 Agent。第一版必须保证离线采集、转写、编辑、已下载资料查看及本地检索；完整离线推理、全量向量库和第二套 DSH 不纳入本次默认范围，若要纳入应明确追加范围，不能默默减少上述离线要求。

## 5. 手机硬件使用要求

### 麦克风与本地语音

“转语言”在本版按前文语境落实为语音转文字，不自动扩展成多语言翻译。先验证设备实际可用的本地语音能力；不可仅因系统有语音输入功能就宣称第三方 App 可离线调用。

如系统服务不适用，ED 应评估可随应用交付或按授权下载的本地识别引擎。必须明确语种、资源版本、大小、许可、初始化方式和真实设备耗时。禁止将联网识别标成离线，禁止静默更换服务商。

模型需要下载时，首次设置须明确完成准备。未准备好时可以先录音，但必须如实显示“离线转写未就绪”；该降级不等于满足最终离线转写验收。首次完全离线安装也能转写，仅在模型已随 APK/配套离线资源包交付后才能承诺。

12 GB RAM 是设备信息，不是速度或可用内存保证。不把 NPU 加速设为先决条件，不凭截图承诺能调用某个硬件加速接口。ED 必须测实际语音响应、内存、耗电和长录音行为。

### 本地存储

明确区分：
1. 未同步原始录音、文字、编辑和待发送意图：可靠业务资料，不属于可自动清理的缓存。
2. 已下载的知识副本：允许按用户策略释放，但待同步修改不能一起删除。
3. 可再生成的预览缓存：可清理。
4. 离线模型：可管理，删除前说明离线转写会不可用。

提供分类占用、剩余空间提醒和本地导出/备份入口。低空间时先告知并保护已保存内容，禁止悄悄淘汰未同步录音。不能承诺卸载或清除应用数据后自动保留所有本地资料。

### 权限与其他硬件

按使用时申请麦克风、文件访问等实际所需权限。不为打开 App 索取全部权限。不把 Google 移动服务作为此 Mate60 的核心依赖。相机采集、系统分享、朗读可列扩展项，不以此阻塞本次核心闭环；后台录音与后台同步分开验证。

## 6. 同步与数据一致性

本机界面读取可靠本地工作副本；统一知识的正式版本仍由灵犀工作台管理。二者分工不同，不建立两个独立演化的知识体系。

内容状态必须分开：
**已保存在手机 → 待发送 / 等待连接 → 正在上传 → 工作台已接收 → 正在处理 → 结果可用 / 需要补充 / 处理失败。**

“已接收”需有可靠接收确认；“处理完成”需有实际结果。Wi-Fi 已连接不代表互联网可用，也不代表工作台可达。

必须保护：稳定采集标识、原始时间及时区、版本、原始音频、初始转写、用户修正版、后台结果；三次重试仍对应同一提交效果。不同记录即使名称相同也不相互覆盖。

两端同时修改同一资料时，保留双方修改，提供对比和选择，不能按最后一次时间戳静默覆盖。后台校正不能覆盖用户已修正的文字。跨天补传仍按实际采集日查找，并分别展示接收和处理时间。

默认保持“本地草稿不外发，主动交给灵犀后才自动恢复传输”；一键开启自动提交须单独明确同意。联网自动同步只涉及已授权的数据和请求，不授予任意外发、删除或执行权限。
