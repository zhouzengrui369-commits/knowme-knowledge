## 1. Owner 已确认的产品方向

Owner 明确确认：未来每个人可以安装自己的灵犀手机 App 和电脑 App，通过账户区分知识底座；手机与电脑使用同一账户的同一套知识，能力层可以分别在各端运行。第一阶段交付 Android APK，连接 NJX 自己的 Mac mini 灵犀工作台和 NJX-Knowledge。手机要能使用硬件、本机语音转文字、持久存储和缓存，能够离线工作，联网后同步。硬件与运行条件允许时手机可承载 DSH/Agent 运行时并直接调用模型 API；依赖电脑的工具仍交给个人服务器。

这份文档记录完整目标和实施边界，不代表这些能力已经实现。已安装 APK 可用是 Owner 对现有 Mate60 的确认；具体系统/API/ABI、麦克风、离线 ASR、内存和后台行为仍由工程真实测量。不得把截图中的设备标识、序列号、IMEI 或账户凭据写进 GitHub。

## 2. 产品定位

灵犀是一套账户绑定、个人知识自主掌控的多端智能工作台。手机不是远程网页壳，也不是只能录音上传的终端；电脑不是所有动作的必经中转。两端分别执行适合本机的能力，共享一个逻辑工作区的知识、记忆、任务和成果。

产品原则：账户决定权限，工作区决定数据归属，设备决定执行位置，连接状态决定当前可用能力。知识统一不等于每次读写都必须在线；Agent 在手机运行不等于把大模型和电脑全部工具塞进手机。

同一通用 APK 不内置 NJX 私人数据、固定账户、密码、服务器密钥或临时公网地址。未来另一用户安装同一 APK，连接自己的账户、工作区和电脑，不访问 NJX 的资料。

## 3. 账户、工作区、设备与服务器

| 对象 | 职责 | 第一阶段 |
|---|---|---|
| account / subject | 证明是谁、持有什么授权；显示名不构成凭证 | NJX 账户，真实认证/设备配对 |
| workspace | 知识、来源、长期记忆、会话任务的逻辑归属 | NJX 私人工作区；正式知识由现有 NJX-Knowledge 管理 |
| device | 本机工作副本、硬件能力、可撤销访问身份 | Mate60 与 Mac mini |
| server | 提供完整知识与远端执行能力的可配置服务 | 现有 Mac mini；公网入口由本机核验，不写死 |

账户、工作区、服务器必须分别标识，不能把用户名当授权，也不能把服务器 URL 当知识所有权。初期允许个人服务器发行本地账户并通过一次性配对/受保护登录授权设备，不要求先建设公共注册中心、收费、组织管理或企业 RBAC。凭据机制由 ED 选型，行为上必须具备拒绝未授权访问、到期/撤销和设备归属。

未来可以有账户目录/中继或托管服务器，但不因此默认上传私人知识到公共中心。跨服务器信任、商业多租户、组织共享不属于本轮。

## 4. 账户与离线语义

从未绑定账户：显示通用壳、连接引导及明确合成的演示，不出现 NJX 的知识、个人对话和身份；不能伪装已经联网运行。首次未绑定时不创建默认归属 NJX 的私人 outbox。

已授权但离线：本机解锁后继续访问获准缓存和该账户本地工作副本；网络令牌失效与本机离线解锁不是同一个状态。展示最后同步时间、知识范围及远端授权是否待验证。

退出/切换账户：旧账户的笔记、录音、检索缓存、对话、模型凭据和待同步任务不能进入新账户。未同步资料不得静默删除，也不得自动上传给新账户；允许回原账户同步、受保护保留或经明确确认导出。全新未登录与已授权离线必须分别验收。

撤销设备：服务器立即拒绝该设备后续在线请求；手机重连后停止同步并提示重新授权。不承诺对完全离线设备瞬时远程擦除；本机数据保护与远端撤销边界必须如实说明。

## 5. 一套知识，多份受控工作副本

工作台管理正式 note_id/revision、原始资料和全量知识组织；手机保存选择性下载、未同步草稿、录音、转写、编辑和 outbox。它们是同一逻辑知识库的工作副本，不是另建第二套正式 Wiki/画像或全量知识主库。

内容至少能区分：原始捕获、本机首次转写、用户修改、工作台补充处理、正式知识版本。原始层不可被后续转写和整理覆盖。知识作者/发言人不能仅凭设备属于 NJX 就自动归因 NJX。

同步按账户/工作区/对象/版本关联。编辑附带基准版本；两端冲突保留双方，明确供用户选择，不静默最后写入覆盖。不同账户不得复用个性化缓存；共享的非私人 ASR 模型文件可复用，但不能夹带用户记忆。

未同步原件不属于可自动清理缓存。清理下载只清可重取副本；删除有未同步修改的资料先提示。卸载或用户清除应用数据不是无限保全承诺；须提供明确说明和受控导出/同步路径。

## 6. 两端能力和 Agent 执行

| 执行位置 | 当前目标 | 不得伪称 |
|---|---|---|
| 手机本地 | 麦克风、录音、本机中文转写、文字/附件保存、本地检索、受控任务编排 | 未验证的 NPU、全量知识访问、离线云模型推理 |
| 手机 + 模型 API | 手机 Agent 使用本地已同步知识和手机工具；工作台离线时仍可运行有网的本端任务 | 把电脑代理执行说成手机执行，或把云端推理说成离线 |
| Mac mini | 全量授权知识检索、既有 DSH、整理/索引、依赖电脑的文件和工具 | 电脑离线时工具仍可用，或已接收即已完成 |
| 外部服务 | 用户明确配置与授权的模型或工具接口 | 静默切换 Provider、绕过数据出境/外发授权 |

优先评估复用现有 DSH 及可在 Android 运行的受支持实现；必须锁定来源、版本、许可和本机实测。硬件允许是可行性条件，不是现成能力。完整 DSH 插件等价不属于本轮；本轮必须交付最小手机端 Agent 编排能力，能在 Mac 不可达但手机有网时调用用户配置模型及至少一个实际手机本地工具。若完整 DSH 不能在目标机运行，可在同一产品行为合同内选轻量可替换运行时；须诚实说明不是完整 DSH，不能退回纯远程网页壳。取消手机独立 Agent 能力必须另提 CR。

远端工具以服务端授权的能力接口调用。手机不因能调用工具而获得任意 Shell、全盘文件或生产执行权限。能力目录应说明执行位置、需要的网络/服务、权限、输入、预期结果和当前可用性。先打通查询、整理、结果预览等已有能力，危险动作不因 Agent 自动规划而获权。

## 7. 任务和会话的一致性

同一任务使用稳定身份，明确主执行端、当前步骤和结果。手机提交远端任务后不能同时自行再执行相同副作用；重试使用同一任务语义和幂等键。桌面和手机显示的可以是同一任务的不同工作面，不要求同步整个 Harness 内存/线程堆栈。

任务最少区分：草稿、等待授权、等待服务器、待执行、运行中、需输入、完成、失败、取消请求中、已取消。取消请求不等于成功撤销已发生的外部动作。离线排队的发送/删除等敏感操作不得因网络恢复自动获得新授权。

结果已生成而完成通知丢失时，恢复应先找回已有结果并关联原任务，不能创建第二主源、第二份正式成果。每项外部副作用单独报告真实状态，禁止虚假“已发送”。

## 8. 三种运行状态

| 状态 | 手机可做 | 需要等待 |
|---|---|---|
| 完全离线且此前已授权 | 录音、本地中文转写、编辑、查已下载知识、准备/取消待同步任务 | 模型 API、全量知识、电脑工具 |
| 手机有网，Mac 不可达 | 以上能力 + 手机 Agent 调模型 API 和本地工具 | Mac 工具和全量知识；明确本地上下文时间/范围 |
| 手机与 Mac 均可达 | 同步知识、继续同一任务、手机本地与远端工具协作 | 不支持/未授权的能力仍不可用 |

任何状态下都必须分别表达：本机保存、网络可用、身份有效、服务器可达、模型可用、工具可用、同步进度。不能用一个绿点冒充全部在线。

## 9. 手机产品设计

保留灵犀现有视觉语言与知识术语，不缩小桌面三栏、不复制另一套产品。四个目的地：灵犀、记录、知识、我的。

灵犀：Agent 对话、当前任务、可接续成果，单手可达的语音/文字/附件输入；显示本机执行或 Mac 执行、知识覆盖范围和待同步数。联网但 Mac 不可用时仍可用手机 Agent，不给假的完整知识回答。

记录：真实录音与输入活动、暂停/继续/停止、时长、低质量警告、本机转写进度、可编辑正文、保留原音、仅本地/交给灵犀选择。录音由用户主动开始，支持已授权的后台/锁屏区间；被系统终止时保全片段并诚实报停。

知识：在线搜索完整授权范围，离线只搜索已下载内容；可查看正文、来源、时间、版本、可离线附件。默认不展示 YAML、文件路径或内部 manifest。正式知识原始来源两步内可达。

我的：账户、工作区、服务器、授权设备、手机模型配置、数据处理去向、本地资源、缓存/同步和退出恢复。高级诊断可访问但不占首屏。

## 10. 数据安全与现有工作台保护

第一阶段为一个真实 Owner、少于十人的私人使用规模；用第二个合成账户验证隔离，不做企业账户平台。重点保护凭证、私密知识/录音、跨账户泄露、不可逆修改和外发。

模型 API 密钥由用户在设备上配置并受保护保存，不能写入 APK、Git、普通日志或知识同步。电脑密钥不自动发给手机。手机/电脑调用外部模型都需说明 Provider、执行位置和哪些上下文会离开本地；“本地知识库”不等于“任何处理都不出设备”。

User 已要求连接自己的知识底座。这授权建设与验证该连接，但不等于任意读取全盘、上传全部私人资料、改变公网路由、替换生产服务或自动外发。采用两阶段运行边界：先在同一 Mac 上隔离工作区/端口/凭据做合成验证；再通过既有认证入口只读访问 Owner 明确选择的 NJX 知识，写操作先进入专用测试工作区。正式 NJX 写入/迁移/公网改路由必须有绑定 exact candidate、目标和回滚条件的单独 Owner 授权。

若现有入口无需生产变更即可使用，则直接验证，不人为增加部署门禁；若需要变更生产，工程准备最小变更清单，不让 PG 代写部署脚本。任何私有原文/录音不随验证报告上传 GitHub，公开证据只用脱敏信息和合成样本。
